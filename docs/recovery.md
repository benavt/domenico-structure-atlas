# Bounded recovery and completion

Preserve the interrupted run and completed target screens. A successor recovery uses its own immutable output directory and exact reviewed library pin. An unfinished temporary array is not a checkpoint just because its allocated file size is correct.

`scripts/recover_screen.py` validates saved intake coverage, native hashes, conformer/chain identity and the exact construct. It recomputes every saved distance vector from original float32 coordinates and requires byte-for-byte equality after the original float16 storage conversion. Every row must pass before terminal diagnostics continue. Rejection flags never exclude models.

`scripts/run_reviewed_plan.py` executes a frozen private plan only after exact plan approval, source/runtime verification, storage preflight and verification of actual cgroup memory/CPU/swap limits. The shared resource guard refuses a busy host, persists telemetry and stops after sustained pressure. No automatic retry or idle-triggered launch is supported. Fleet supplies storage protection and machine bindings.

After screening review, freeze the retained axes for standard analysis: PCA/UMAP/t-SNE, validated shared clusters, genuine confidence and explicit unscored-medoid selection, energy/physicality plots, complete PowerPoint, full-atom ensembles/PyMOL, TM grids and Bonsai. Molecular completion retains its recorded camera-approval gate. Saved publication retains every accepted model ID, projection point, score and membership row, but publishes coordinate files only for cluster representatives and explicitly selected saved state panels by default. Plot and Bonsai point selections show the associated cluster representative; full original inputs and historical releases remain preserved. Merges, scientific execution and public deployment keep their separate exact approvals.

Retain measured peak memory, wall time, numerical parity and any failure alongside the recovery plan. Synthetic benchmarks do not establish full-cohort performance.

Runtime pressure uses actual stall-counter deltas over each sampling interval; a decaying ten-second average after one transient is not sustained pressure. Admission retains the conservative smoothed-average check and all percentage limits. Verification receipts are atomically saved and synced every 50 models. An explicitly selected prior checkpoint is reused only when verifier/engine/parser versions and all input/distance hashes match; the frozen plan must authorize that reuse.


The publication plan defaults to `"structure_delivery": "representatives"`. It does not create an all-model coordinate directory or require/repackage an original-model archive. Full-atom representatives, their saved ensemble metadata, all three full-cohort projections, confidence/energy/physicality coloring and complete membership/score CSVs remain available. Per-state MCMC50/DISCO50 artifacts must come from an explicitly selected, validated scientific result; missing state or Bonsai results are never fabricated by publication.

`"structure_delivery": "all-point-ca"` is an explicit compatibility option for historical full-point releases. It retains exact C-alpha files, display/native hashes and the verified complete original archive requirement. It is not the default for a new atlas. Published history and native scientific source files are not deleted when creating a new representative-only candidate.

A saved target may add `density_artifacts` with hash-bound `labels_csv`, `ensemble_report`, `analysis`, `bonsai` and `medoid_tm` descriptors (`path` and `sha256`). The completed analysis must identify HDBSCAN, the exact target/workflow, full ordered model IDs, their compact-JSON SHA-256, `model_count`, the identical density labels and its recorded method. This creates a curated HDBSCAN default view alongside the original UMAP KNN view. Unassigned density models retain every point and score but receive no representative, ensemble or medoid-grid row. Bonsai geometry and TM matrices are copied from saved scientific results; publication performs no fitting or similarity calculation.

`build(plan, export_site=False)` prepares the source datasets and returns their exact view hashes, model order, construct scope and publication manifest. A controller may then attach separately verified saved state payloads and panels; `export_prepared(prepared)` refreshes the file allowlist and exports the shared renderer once. This source-preparation hook does not publish, change a dependency pin, or authorize scientific execution. The command-line publisher retains its existing single-export behavior.

Optional `region_artifacts` binds a derived manifest, derived ensemble report and annotated image by SHA-256. A presentation-only copy may add the saved variance heatmap palette and a `presentation_derivation` proof; the original numerical results, residue masks, full source population, core definitions and projection paths must remain identical. The shared residue-scope reader verifies the native residue map and authoritative colors before publishing those empirical cores in either view. These cores are explicitly separate from biological domain assignments and TM-defined states.

For the measured RBP I/O stop, grouped durable persistence and the proposed cooperative guard, see [I/O diagnosis and remaining recovery](io-recovery.md). The saved HDBSCAN/Bonsai/TM results and representative-only Pages release can proceed independently of the remaining state search.
